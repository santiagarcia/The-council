# Contributing

Read AGENTS.md, the charter, and the constitution. Start with an issue or bounded objective in project context, identify one owner, and preserve existing work. Use an isolated Python environment and an editable install with the dev extra.

Keep changes focused. For technical claims supply reproducible evidence and arrange a reviewer independent of implementation. Record disagreements, limitations, and the minimum additional test needed. The PR template asks for scope, affected identities or memories, evidence, verification, risks, and rollback.

Before a local commit run tests, lint, formatting checks, and Council validation. Inspect status and staged paths. Do not publish confidential code, deck content, credentials, or collaborators' unpublished results. Do not push or contact collaborators without explicit authority. Use CODEOWNERS.example as a reviewed starting point, not as an invented ownership assignment.

New identity behavior needs a visible proposal and evaluation trial. New record fields need schema, validation, and compatibility decisions. Explain migrations before changing stored data. Update user-facing command documentation when behavior changes.
