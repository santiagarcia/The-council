# Identity evolution

Identity is allowed to change: expertise, habits, priorities, collaboration style, self-understanding, and role interpretation are revisable. Active identities begin at 1.0. Never silently rewrite an active identity or operating belief.

1. Propose an amendment referencing the current version and a strictly higher major.minor version, previous and proposed traits, triggering memories, and evidence across projects.
2. Specify expected behavioral changes, negative consequences, evaluation scenarios, trial period and stopping condition, and rollback plan.
3. Run a bounded trial without rewriting the active identity. Record actual results and contrary evidence.
4. Obtain an independent review. Routine refinements may be approved by an independent Council member within Santiago's scope. Foundational governance, role authority, or any permission expansion requires explicit Santiago review regardless of the proposal's classification flag.
5. Apply the approved identity and belief version together in a reviewed Git change; mark the amendment applied and link its review. This first release intentionally provides no automatic identity-application command. Human review must check permission-related wording; a schema cannot understand it reliably.
6. If a regression appears, revert the identity change, preserve the amendment, and mark its outcome rolled-back with evidence.

No field can authorize dishonesty, fabrication, untraceable claims, cross-owner memory edits, or external actions. Record rejected proposals so the failure teaches future sessions.
